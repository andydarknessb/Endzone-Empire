# Draft-room screenshot matrix

A committed, human-browsable record of what the released Draft room actually
looks like: one PNG per layout and interactive state, so a reviewer can inspect
the set as ordinary files rather than by decoding a Playwright HTML report.

These images are generated by `tests/e2e/draft-accessibility.spec.ts` (issue
#548), which owns the single screenshot mechanism. Each capture is taken against
the controlled local Draft harness (mocked REST + Socket.IO, the `Harness
League` fixture): no production, no real league, no database.

## Regenerate

From the repo root, with the client already reusable at `127.0.0.1:4173` (the
e2e config starts it for you outside CI):

```
npx playwright test --config=playwright.e2e.config.js tests/e2e/draft-accessibility.spec.ts
```

Run it with the config's own reporters. Do **not** pass `--reporter=list`: that
overrides the config's reporter array and drops the `html` reporter, so the run
still passes but writes no report attachments.

The spec rewrites every file in this folder on each run. The set is
deterministic (animations frozen, caret hidden, fonts awaited, timezone and
locale pinned, and a non-viewer turn so the transient on-the-clock snackbar
never fires), so a clean regeneration leaves `git status` clean.

## Capture scope is in the filename

Each filename says its scope so a reader never assumes the wider one:

- `room-*` is a **viewport** capture: the whole Draft room, what a user sees
  without scrolling. The wide layout uses `VIEWPORTS.desktop` (1280x900, three
  panes), the narrow layout `VIEWPORTS.mobile` (390x844, tabs) - the same
  constants the original three captures use, so the set stays comparable. The
  room's shell is pinned to exactly the viewport height (draft-board.spec.ts,
  #122), so the page never scrolls; overflow goes into each region's own
  scroller, which is why a region-specific state is captured as an element.
- `region-*` is an **element** capture (`locator.screenshot()`): one region,
  framed whole regardless of where its own scroller sits. Used for states that
  live inside a scroller or a portal overlay (the chat log, the composer, the
  emoji menu), where a viewport shot could clip them.
